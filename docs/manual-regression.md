# 手动回归清单

需真机 + 真站点，自动化无法覆盖。每次发版执行。
以下四项来自 PakePlus-Android 的实际踩坑记录。

- [ ] **WASM streaming compile** —— 加载依赖 `WebAssembly.instantiateStreaming` 的站点。
      已有 shim 修复经验，若复发按同样思路在注入脚本里补 shim。
- [ ] **`blob:` / `data:` URL 下载** —— 触发一次页面内导出/下载，确认文件真的落盘。
- [ ] **输入法遮挡** —— 点页面底部输入框，确认键盘不遮挡（`windowSoftInputMode=adjustResize`）。
- [ ] **4K 视频播放** —— Pixel 8 已验证基线，确认不卡顿、不黑屏。

外加壳自身的四项：

- [ ] 底部浮层上的 ⚙ 能打开设置（在**网页白屏时**也要试一次）。
- [ ] 改 URL → 页面跳转；重启 app 后仍是新 URL。
- [ ] 切 UA → 页面 reload，站点识别为对应设备。
- [ ] 「重置」后回落到构建时的 URL 与 UA。
- [ ] 关掉一个注入脚本开关（比如 Capture network）→ reload 后脚本真的不生效了，
      不是只改了存储值。
- [ ] 栏可见时，网页底部两侧的按钮仍能点到——遮挡是已知代价，
      但不能宽到把整条底部都吃掉。

底部悬浮栏（`docs/superpowers/specs/2026-08-18-bottom-bar-design.md`）：

- [ ] **`onScrollChanged` 的 y 单位** —— 打印一次实际值。Android 原生给的是
      设备像素，插件是否转成逻辑像素没在源码里确认到；若是设备像素，10px
      阈值在 3x 屏上会过于灵敏，需要按 `devicePixelRatio` 换算。
- [ ] **内层滚动容器** —— 有些站点滚在内层 `div` 而非 document 上，
      `onScrollChanged` 不触发，「上滑隐藏」在那类站点上不生效（不会砖，
      栏保持可见）。确认目标站点属不属于这种。
- [ ] 上滑隐藏 / 下滑显示跟手，10px 阈值不抖。
- [ ] 滑到页面顶部时栏必然出现。
- [ ] 从长页面点进不可滚动的短页面，栏必然出现（这是「卡在隐藏态」的主要
      死锁场景）。
- [ ] 视频进全屏时栏消失，退出全屏时回来。
- [ ] 后退按钮在首页是灰的，点进二级页后变亮。
- [ ] 系统返回键：有网页历史时回退，无历史时退出 app。
- [ ] **锁屏亮着时按系统返回键——什么都不做，解锁后页面没变。**
- [ ] 刷新按钮停在当前页，不回首页。
- [ ] **毛玻璃滚动性能** —— `BackdropFilter` 叠在 WebView 之上，滚动长页面时
      看有没有掉帧。掉帧就先降 `ImageFilter.blur` 的 sigma（当前 20）。
- [ ] **浅色网页上的可读性** —— 深色玻璃 + 白图标是钉死的，没有跟随逻辑。
      在浅色站点上确认图标还认得出；认不出就是已知代价，不是 bug，但值得
      记下有多糟。

分享：

- [ ] 从首页点进二级页再点 ⋯ → Share，系统面板里带出来的是**那一页**的标题和
      地址，不是首页——这条是自动化测不到的，`getUrl()` 走的是平台通道。
- [ ] 分到一个只读 `EXTRA_TEXT` 的 app（微信、QQ）里，标题和链接两行都在。

检查更新（`docs/superpowers/specs/2026-08-21-update-check-design.md`）：

- [ ] 发一个更高版本的 release 后冷启动 → 弹出提示，点「更新」跳到系统浏览器
      并真的下到 APK。**这一条同时验证了 `<queries>` 里的 https VIEW intent**
      ——缺了它按钮点了没反应，任何单元测试都看不到。
- [ ] **开着应用锁**冷启动 → 解锁之后才看到弹窗，而不是解锁后什么都没有
      （锁屏盖在 navigator 之上，弹早了等于白弹掉一次额度）。
- [ ] 覆盖安装成功 —— 这同时是「发布用的 keystore 跟已装那版一致」的唯一验证。
- [ ] 点「稍后」后重启 app 不再弹；发一个更高版本后重新弹。
- [ ] 飞行模式冷启动：无任何提示、无卡顿、不掉进错误页。
- [ ] 设置页手动「Check for updates」：无新版时明确说「Already on the latest」，
      断网时说「Check failed」——手动路径必须有确定答复。

**测这几条之前先按顺序做两件事**，否则测出来的「没弹」全是假的：

1. 设置页 **Reset to build defaults** —— 清掉「上次检查时间」（24 小时内不再查）
   和「已忽略的版本」（点过一次 Later 就再也不弹那一版）。
2. 点一次 **Check for updates** 确认看得到「Version x is available」。手动路径
   不写时间戳、也不看「已忽略版本」，所以这一步既证明「这次确实有东西可弹」，
   又不会把冷启动那次的额度提前用掉。

之后**中间不要冷启动**——任何一次冷启动都会把额度用掉。改过 GitHub 上的
prerelease 勾选的话还要再等一分钟：未登录的 `api.github.com` 响应有约 60 秒
CDN 缓存。
